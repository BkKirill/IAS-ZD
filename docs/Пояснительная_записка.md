## 1. Описание проекта

### 1.1 Актуальность

Состояние железнодорожной инфраструктуры (станций, мостов, переездов, участков пути) зависит от погоды и от
проводимых ремонтных работ. Сильные морозы и жара вызывают температурные деформации рельсов, сильный ветер и
снегопады приводят к ограничениям движения, а плановые «окна» меняют расписание поездов.

Эта информация публикуется в разных местах: погода — в погодных сервисах, ремонты и ограничения — в новостях
ОАО «РЖД», расписание — в сервисах расписаний. Единого открытого инструмента, который собирает эти данные
вместе и показывает их на карте, нет.

### 1.2 Цель

Разработать веб-систему, которая автоматически получает информацию из открытых российских источников,
анализирует её, отображает состояние объектов железнодорожной инфраструктуры на интерактивной карте,
ведёт историю наблюдений и формирует отчёты.

### 1.3 Задачи

1. Найти открытые наборы данных и сервисы, связанные с железной дорогой (только российские).
2. Проанализировать существующие системы мониторинга.
3. Сформулировать требования к системе.
4. Предложить и описать архитектуру ИС с возможностью подключения новых источников и модулей анализа.
5. Реализовать прототип системы.

### 1.4 Объект и предмет

- **Объект** — объекты железнодорожной инфраструктуры Самарской области (Куйбышевская железная дорога —
  филиал ОАО «РЖД»): станции, мосты, переезды, участки пути.
- **Предмет** — процессы сбора, анализа и отображения открытых данных о состоянии этих объектов.

### 1.5 Пользователи системы

| Роль | Что делает |
|---|---|
| Наблюдатель | смотрит карту, историю и отчёты |
| Оператор | вносит сведения о ремонтах и ограничениях, загружает CSV |
| Администратор | настраивает источники данных (ключи API, интервал опроса), объекты |

### 1.6 Функциональные требования

1. Автоматический сбор данных из источников по расписанию (интервал настраивается) и по кнопке.
2. Хранение справочника объектов инфраструктуры с координатами.
3. Анализ данных и присвоение объекту состояния: **норма / неблагоприятная погода / ремонт / закрыто**
   с указанием причин.
4. Отображение объектов на интерактивной карте с цветом по состоянию и всплывающей карточкой.
5. Ведение истории наблюдений с графиком по объекту.
6. Учёт ремонтных работ и ограничений движения (ручной ввод и импорт из CSV).
7. Формирование отчёта за период с выгрузкой в CSV (Excel) и печатью в PDF.
8. Журнал работы источников данных (успешно / ошибка).

### 1.7 Нефункциональные требования

- Используются только российские сервисы для сбора данных и отображения карты.
- Веб-интерфейс, работа в любом современном браузере.
- Отказ одного источника не останавливает работу системы (ошибка пишется в журнал).
- Новые источники данных и правила анализа добавляются без переделки остальных частей.

## 3. Анализ существующих систем

### 3.1 Внутренние системы ОАО «РЖД»

| Система | Назначение | Доступность |
|---|---|---|
| ЕК АСУИ (Единая корпоративная автоматизированная система управления инфраструктурой) | учёт объектов инфраструктуры, отказов, планирование ремонтов | только для сотрудников РЖД |
| АСУ-П (путевое хозяйство) | учёт состояния пути, результатов диагностики | только для сотрудников РЖД |
| ГИД «Урал-ВНИИЖТ» | график исполненного движения поездов в реальном времени | только для сотрудников РЖД |
| Системы метеомониторинга на дорогах | получение метеоданных для диспетчеров | только для сотрудников РЖД |

Эти системы полноценные и точные, но **закрыты** и используют данные с датчиков и диагностических средств,
а не открытые источники.

### 3.2 Публичные сервисы

| Сервис | Что показывает | Чего нет |
|---|---|---|
| Яндекс Расписания / Яндекс Электрички | расписание, изменения расписания | состояния инфраструктуры, погоды на объектах, истории, отчётов |
| Туту.ру | расписание, билеты | то же |
| Приложение «РЖД Пассажирам» | билеты, расписание, новости | карты состояния объектов, аналитики |
| Яндекс Погода / Гисметео | погода | привязки к ж/д объектам |

### 3.3 Сравнение

| Возможность | Внутренние системы РЖД | Публичные сервисы | Разрабатываемая система |
|---|---|---|---|
| Открытый доступ | – | + | + |
| Карта объектов инфраструктуры | + | – | + |
| Погода на объектах | + | – | + |
| Ремонты и ограничения | + | частично | + |
| Оценка состояния объекта | + | – | + |
| История наблюдений | + | – | + |
| Отчёты | + | – | + |
| Только открытые данные | – | + | + |

**Вывод.** Внутренние системы недоступны, публичные сервисы показывают данные по отдельности.
Разрабатываемая система занимает нишу открытого инструмента, который объединяет данные из нескольких
российских источников в одном месте.

## 4. Архитектура информационной системы

### 4.1 Общая схема

Система построена по модульному (слоистому) принципу:

```
┌───────────────────── Источники данных (российские сервисы) ─────────────────────┐
│  Яндекс Погода API     Яндекс Расписания API     Сайты РЖД (ручной ввод / CSV)   │
└──────────┬───────────────────────┬─────────────────────────────┬────────────────┘
           ▼                       ▼                             ▼
┌───────────────────────── Модуль сбора данных ──────────────────────────────────┐
│  YandexWeatherCollector   YandexRaspCollector   …новый сборщик   │ планировщик  │
└──────────────────────────────────┬──────────────────────────────────────────────┘
                                   ▼
┌────────────────────────── Модуль анализа ──────────────────────────────────────┐
│  правило «температура»  правило «ветер»  правило «осадки»  правило «ограничения»│
│              → состояние: норма / погода / ремонт / закрыто + причины           │
└──────────────────────────────────┬──────────────────────────────────────────────┘
                                   ▼
┌────────────────────────── База данных (SQLite) ────────────────────────────────┐
│  objects   observations   restrictions   collector_log                          │
└──────────────────────────────────┬──────────────────────────────────────────────┘
                                   ▼
┌────────────────────────── Веб-сервер (Flask) ──────────────────────────────────┐
│  страницы: карта, история, ограничения, отчёты, источники;  JSON API            │
└──────────────────────────────────┬──────────────────────────────────────────────┘
                                   ▼
┌────────────────────────── Веб-интерфейс (браузер) ─────────────────────────────┐
│  Яндекс Карты JS API — карта объектов;  таблицы;  график истории;  отчёт/CSV    │
└─────────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 Модули

1. **Модуль сбора данных** (`collectors/`). Каждый источник — отдельный класс-наследник `BaseCollector`
   с методом `collect(объект, дата)`. Все сборщики перечислены в списке `COLLECTORS`. Планировщик
   запускает их по очереди с заданным интервалом. Ошибка одного источника записывается в журнал
   и не мешает остальным.
2. **Модуль анализа** (`analysis.py`). Набор правил; каждое правило смотрит на данные и возвращает
   категорию (погода, ремонт, закрыто), подпись и причину. Итоговое состояние — самая важная из сработавших категорий.
3. **База данных** (`db.py`). Хранит справочник объектов, историю наблюдений, ремонты/ограничения,
   журнал источников.
4. **Веб-сервер** (`app.py`). Отдаёт страницы и JSON API для карты и графиков.
5. **Веб-интерфейс** (`templates/`, `static/`). Карта на Яндекс Картах, таблицы, график, отчёты.

### 4.3 Правила анализа (прототип)

Состояние объекта показывается не абстрактным уровнем опасности, а по сути события:

| Категория (цвет на карте) | Подпись | Когда присваивается |
|---|---|---|
| Норма (зелёный) | «норма» | ни одно правило не сработало |
| Неблагоприятная погода (синий) | «сильный мороз» / «жара» | температура ≤ −25 °C или ≥ 30 °C |
| | «сильный ветер» | ветер с учётом порывов ≥ 15 м/с |
| | «сильные осадки» | сильный снегопад или ливень |
| Ремонт (оранжевый) | «ремонт» / «ограничение скорости» | на объекте действует запись о ремонте или ограничении скорости |
| Закрыто (красный) | «движение закрыто» | на объекте действует запись о закрытии |

Если сработало несколько правил, показывается самая важная категория (закрыто → ремонт → погода → норма),
а все причины перечисляются в карточке объекта. Пороги условные и легко меняются в коде.

### 4.4 Структура базы данных

| Таблица | Поля | Назначение |
|---|---|---|
| `objects` | id, name, type, region, lat, lon, rasp_code | объекты инфраструктуры |
| `observations` | id, object_id, ts, source, temp, wind, gust, precip, condition, trains_today, status, label, reasons | история наблюдений |
| `restrictions` | id, object_id, kind, description, start_date, end_date, source | ремонты и ограничения |
| `collector_log` | id, ts, collector, ok, message | журнал работы источников |

Связи: `observations.object_id → objects.id`, `restrictions.object_id → objects.id` (один ко многим).

### 4.5 Расширяемость

- **Новый источник данных** — новый файл в `collectors/` с классом-наследником `BaseCollector`
  и одна строка в списке `COLLECTORS`. Например: штормовые предупреждения Гидрометцентра,
  открытые данные Самарской области.
- **Новый модуль анализа** — новая функция-правило и одна строка в списке `RULES`.
  Например: сравнение числа поездов с обычным для этого дня значением.
- **Масштабирование** — SQLite заменяется на PostgreSQL без изменения логики, планировщик — на
  отдельную службу.

## 5. Реализация прототипа

Прототип реализует все функции из п. 1.6. Страницы:

- **Карта** — объекты на Яндекс Картах, цвет метки по состоянию; клик открывает карточку с погодой,
  числом поездов, действующими ограничениями и причинами состояния. Кнопка «Обновить данные сейчас».
- **История** — таблица наблюдений по выбранному объекту и график температуры и ветра.
- **Ограничения и ремонты** — список с отметкой «действует / планируется / завершено», форма ввода,
  импорт CSV.
- **Отчёты** — сводка по объектам за период: число наблюдений, мин./макс. температура, макс. ветер,
  число наблюдений с неблагоприятной погодой, ремонтом и закрытием, число записей о ремонтах;
  выгрузка в CSV и печать.
- **Источники** — список подключённых сборщиков и журнал их работы.

Все данные в системе реальные: погода — из API Яндекс Погоды, число отправлений поездов со станций —
из API Яндекс Расписаний (коды станций определяются автоматически по координатам и сохраняются
в справочнике), карта — API Яндекс Карт. Для отладки без ключей предусмотрен тестовый режим
(`DEMO_IF_NO_KEY=1`), по умолчанию он выключен.

## 6. Заключение

В ходе практики:

1. Описан проект: цель, задачи, пользователи, требования.
2. Найдены и проанализированы российские открытые источники данных, связанные с железной дорогой.
   Установлено, что прямых открытых данных о состоянии пути нет, поэтому используются косвенные данные
   (погода, движение поездов, публикуемые сведения о ремонтах).
3. Проанализированы существующие системы: внутренние системы РЖД закрыты, публичные сервисы не
   объединяют данные.
4. Предложена модульная архитектура с возможностью подключения новых источников и модулей анализа.
5. Реализован работающий прототип веб-системы.

**Направления развития:** подключение штормовых предупреждений Гидрометцентра и МЧС, автоматический
разбор новостей РЖД о ремонтах, сравнение числа поездов с обычными значениями, уведомления оператору,
разграничение прав пользователей.
